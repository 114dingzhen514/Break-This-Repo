# 冒泡排序动画演示（C / Windows 控制台）

用条形图逐帧演示冒泡排序的过程：正在比较的元素、发生交换的瞬间、每一轮结束后归位的元素，
都分别用颜色标出来。**要排序的数据完全由你决定**——命令行、输入向导、排序后实时编辑，
想怎么改就怎么改，不用退出程序重开。

```
冒泡排序动画演示   元素 9 个   第 1 轮   比较 1 次   交换 0 次
当前比较: a[0]=42  与  a[1]=36 -> 需要交换!

                                ###            <- 条子高度 = 数字大小
  ##             ##        ##  ###            <- 绿色 = 已归位
  ##   ##        ##   ##   ##  ###        ##  <- 黄色 = 正在比较
  ##   ##        ##   ##   ##  ###        ##  <- 红色 = 正在交换
  ##   ##    #   ##   ##   ##  ###    #   ##
                                             <->   <- 发生交换时出现
---------------------------------------------
42   36   6    44   35   40   64   2    37
从左到右两两比较, 前面比后面大就交换
```

## 一、编译

需要 MinGW-w64 的 gcc（本机在 `C:\Programs\Mingw64\bin\gcc.exe`）。

```bat
gcc -O2 -Wall -Wextra -std=c99 -o bubble_sort_anim.exe bubble_sort_anim.c
```

MSVC 也可以：

```bat
cl bubble_sort_anim.c
```

> **踩过的坑（重要）**：MinGW 的汇编器**无法写入含中文的绝对路径**。
> 在中文路径下用 `gcc -o C:\...\中文目录\x.exe` 会报
> `can't create ...: No such file or directory` / `cannot open output file`。
> 解决办法：先 `cd` 到源文件所在目录，用**相对文件名**做输出。
> 本目录的 `.vscode/tasks.json` 已经这样配好了。

## 二、四种自定义数据的方式

### 方式 1：命令行直接给数据

```bat
bubble_sort_anim.exe 5 3 8 1 9 2
bubble_sort_anim.exe 42 7 19 3 88 56 23 71 4
```

### 方式 2：输入向导（不带数字运行）

程序会先问你用哪种录入方式，再收集数据：

```
=========== 自定义原始数据 ===========
  1    一行输入全部数字   例: 5 3,8 1,9 2
  2    先定数量, 再逐个输入 (带即时校验)
  3    随机生成一组
  0    退出程序
=====================================
请选择 [0-3]: 2

先告诉我这一组要排几个数, 然后一个一个输入。
元素个数 (回车 = 5, 输入 q 取消): 3
  第 1/3 个 (q 取消整组): 5
      已记下 5, 当前: 5
  第 2/3 个 (q 取消整组): abc
  'abc' 不是整数。
  第 2/3 个 (q 取消整组): 7
      已记下 7, 当前: 5 7
  第 3/3 个 (q 取消整组): 8
      已记下 8, 当前: 5 7 8

这一组原始数据 (3 个):
  5 7 8
就用这一组开始排序? [Y/n]
```

- **方式 2 的逐个录入**：先定数量，再一个一个输入，**每输一个立刻校验并回显**，
  输错了当场重来，不会等到最后才发现；中途输入 `q` 可以取消这一组，
  程序会重新问你"要几个"，而不是把你踢回主菜单。
- 数字之间用**空格或逗号**都行（`5 3,8 1,9 2` 等价于 `5 3 8 1 9 2`）。
- 录完会**回显确认**，选 `n` 就重新来一遍。
- 输入 `1e9`、`abc` 这类非法词会被跳过并提示，数字不够就在**原地重问**，不用重选菜单项；
  只给了 1 个数字会提示至少要 2 个。

### 方式 3：排序结束后实时编辑（不用重开程序）

每轮动画跑完会自动进入编辑菜单，可以直接改数据再重跑。菜单长这样
（下面用 `--delay-ms 30 42 7 19 3 88 56 23 71 4` 跑，也就是"运行 (自定义数据菜单)"那个任务）：

```
最终结果: 3 4 7 19 23 42 56 71 88
共比较 36 次, 交换 17 次。
(n=9 的冒泡排序, 最坏情况需要 n(n-1)/2 = 36 次比较)

------------------ 编辑原始数据 ------------------
  当前数据 (9 个): 3 4 7 19 23 42 56 71 88
  每帧 30 毫秒
  [e]改一个 [a]追加 [d]删除 [i]插入 [p]粘贴 [s]打乱 [g]随机
  [t]调速 [l]列出 [r]重跑(回车) [q]退出
请选择:
```

| 按键 | 作用 |
| --- | --- |
| `e` | 改某一个元素（问下标和新值） |
| `a` | 在末尾追加若干个元素（受 128 上限约束） |
| `d` | 删除某一个元素（剩 2 个时会拦住你） |
| `i` | 在指定位置插入一个元素 |
| `p` | 粘贴一整行新数据，整组替换 |
| `s` | 把当前数据打乱成随机顺序 |
| `g` | 随机生成一组新数据（可指定个数） |
| `t` | 调整每帧毫秒数，`0` = 不停顿（飞快） |
| `l` | 列出全部数据 |
| `r` / 直接回车 | 用当前数据**重新跑一遍动画** |
| `q` | 退出程序 |

每次操作后都会回显操作结果和最新数据，改完按 `r` 或回车立刻重看动画。

### 方式 4：随机生成

```bat
bubble_sort_anim.exe --random 15 --delay-ms 20
bubble_sort_anim.exe --random 10 --seed 42      :: 同一个种子 = 同一组数据
```

`--seed` 让随机结果可复现，方便对比调试或者把某组"难看的"数据固定下来。

## 三、参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--delay-ms N` | 每帧间隔毫秒数（0~5000），越小动画越快 | 40 |
| `--scale N` | 每个数字占几列（3~12），决定条子宽度 | 5 |
| `--random N` | 随机生成 N 个 1~99 的数，省得手打 | 关 |
| `--seed N` | 随机种子，配合 `--random` 复现同一组数据 | 时间 |
| `--no-color` | 关闭颜色（重定向到文件时用） | 关 |
| `--help` | 显示帮助 | — |

例子：

```bat
bubble_sort_anim.exe --random 15 --delay-ms 20      :: 15 个随机数, 快速播放
bubble_sort_anim.exe --scale 8 9 8 7 6 5            :: 条子粗一点
```

数字较多时列宽会自动缩小；如果屏幕宽度实在放不下（`宽 / 个数 < 3`），程序会提示你
减少数量或者把窗口拉宽——在交互模式下会直接回到编辑菜单，这时按 `p` 粘贴一组短数据、
或按 `g` 换一组少的，就能继续演示（管道/重定向输入时没法问你，会直接退出）。

## 四、怎么看这个动画

- **条子高度** = 数字大小（按当前数组最大值等比缩放，所以最小的数也有 1 格，不会看不见）
- **黄色** = 这一帧正在比较的两个元素
- **红色 + `<->` 箭头** = 这两个元素正在交换
- **绿色** = 已经排好、后面不再参与比较的元素（冒泡排序每轮结束都会锁定最右边一个）
- **灰蓝色** = 还没排到的元素
- 顶部实时显示：轮数、累计比较次数、累计交换次数

每个比较动作会画 2~3 帧：先亮出比较的一对 → 如果需要交换，变红并显示箭头 → 显示交换后的结果。

## 五、算法说明

核心就是教科书里的冒泡排序，加了一个优化：

```c
for (i = 0; i < n - 1; i++) {
    swapped = 0;
    for (j = 0; j < n - 1 - i; j++) {
        if (a[j] > a[j + 1]) {
            swap(a[j], a[j + 1]);
            swapped = 1;
        }
    }
    if (!swapped) break;      /* 一趟下来没交换 -> 已经有序, 提前结束 */
}
```

- 内层上界是 `n - 1 - i`：每轮结束后最右边 i 个元素已经就位，不用再比
- `swapped` 标记：整趟没有交换说明数组已经有序，直接退出
- 时间复杂度 O(n²)，最好情况（已有序）O(n)；空间复杂度 O(1)，稳定排序

### 兼容性 / 不挂死

程序会分别判断 **stdout 是不是真控制台**（决定能不能"就地重画"）和
**stdin 能不能问答**（决定要不要进菜单），两者不是一回事：

| 测试场景 | 结果 |
| --- | --- |
| 管道里只给数字（`echo ... \| exe`） | ✅ 跑完自动跳过编辑菜单，不阻塞等待输入 |
| 管道里不给数字 | ✅ 明确报"没法进入输入向导"，退出码 1 |
| stdout 不是控制台（管道 / 重定向 / VS Code 调试控制台） | ✅ 自动降级成**逐行文本画面**，不用光标定位、不清屏 |
| `--no-color` 重定向到文件 | ✅ 文件里 **0 个 ESC 字符**，无乱码 |
| `--bogus` / `--scale`（缺数值）/ `--delay-ms 99999` | ✅ 均给出明确错误，退出码 1 |
| 窗口 80 列放 120 个元素 | ✅ 提示"数字太多…放不下"并提示减少数量 |

**stdout 不是控制台时**（比如 VS Code 的"调试控制台"、`exe > out.txt`），
`gotoxy` 定位会失效、`\x1b[2J` 清屏会被当成换页符印出乱码，画面会一行行堆在一起。
所以这种情况下程序自动换成逐行文本画面，一行一帧：

```
原始数据 (5 个):
  5 3 8 1 2
(标准输出不是控制台: 用逐行文本方式演示, 不做原地重画)
 1 |[5 3] 8  1  2    比较1 交换0  a[0]=5 vs a[1]=3
 1 |<5 3> 8  1  2    比较1 交换0  a[0]=5 vs a[1]=3 交换
 1 |<3 5> 8  1  2    比较1 交换1  a[0]=3 vs a[1]=5 交换
 1 |3  [5 8] 1  2    比较2 交换1  a[1]=5 vs a[2]=8
```

约定：`[a b]` = 正在比较，`<a b>` = 正在交换，`5.` = 该元素已归位，
`#` = 大于 9 的数（末位数字放不下就不显示）。这种输出也是**可以直接 grep 的排序轨迹**，
重定向到文件就能当验证日志用。

> 交互流程的自动化测试用了 `BUBBLE_ANIM_FORCE_TTY=1`（见下），
> 它把管道输入当成控制台，从而能用脚本喂按键、确定性地验证向导和菜单。

## 七、VS Code 用法

本目录已带 `.vscode/` 配置：

- **Ctrl+Shift+B** → 编译（默认构建任务）
- **终端 → 运行任务 → 运行 (随机 10 个数字)** → 编译并跑一段演示
- **运行 (输入向导)** → 编译后不带数字运行，直接体验自定义数据向导
- **运行 (自定义数据菜单)** → 编译后带一组数据跑，回车即可进编辑菜单
- **F5** → 调试，两个配置按需选：
  - **调试 (外部控制台, 有完整动画)** —— 推荐，会弹一个真正的控制台窗口，
    有颜色和原地重画的条形图动画 ⚠️
  - **调试 (集成控制台, 逐行文本)** —— 在 VS Code 内部"调试控制台"里跑，
    没有动画，但能一行一帧看清每一步

> ⚠️ **VS Code 的"调试控制台"不是真控制台**：它的输出是管道，
> 光标定位和清屏都不生效，所以那里看不到条形图动画。
> 想看完整动画就用 **F5 的"外部控制台"配置**，或者在系统里直接跑 exe。
> 程序会自动识别这种情况并降级成逐行文本，不会印出乱码，也不会卡住等人按回车。

如果颜色显示不正常（比如在很老的 cmd.exe 里），加 `--no-color`，程序会自动改用
Win32 控制台颜色 API。中文显示成乱码的话，换 **Windows Terminal**，或者先执行：

```bat
chcp 65001
```

## 八、给自动化测试用的小开关

```bat
set BUBBLE_ANIM_FORCE_TTY=1
echo q | bubble_sort_anim.exe 5 3 1
```

`BUBBLE_ANIM_FORCE_TTY=1` 让程序**整个假装成真控制台**，即使从管道读输入也会走完整的
交互流程（向导 + 编辑菜单），方便写脚本回归测试或录演示；它同时会去掉"按回车开始动画"
这类等人操作，画面仍走上面的逐行文本形式。
只想单独试"输出端当成控制台"（ANSI 重画那条路径）就用 `BUBBLE_ANIM_FORCE_TTY=2`。
正常使用不需要它。
